## 01 // PROBLEM
Raw Accel is the driver a lot of FPS players use for mouse acceleration, and its math is excellent. Its settings window is harder: you change a number, write it to the driver, then move the mouse to find out what you did. Some options exist only in the JSON file.

I wanted to see the curve change while I typed, and to compare it with what the driver has right now, before writing anything.

## 02 // APPROACH
- **Live plot from the driver's own code.** The solid curve is what I'm editing, computed through Raw Accel's `wrapper.dll`; the dashed one is what the driver has now. A marker follows my real hand speed.
- **Every option gets a control.** Angle snapping, speed cap, per-axis multipliers and smoothing were JSON-only before.
- **Profiles and devices.** Multiple profiles, per-mouse DPI and polling rate, undo and redo, and an aim test that runs the same drill on each profile and ranks them, with a blind mode.
- **Change only the window.** The driver, the math and the settings format are Raw Accel's, untouched, so `settings.json` still works with the original GUI and `writer.exe`.

## 03 // BUILD
The host is C# on .NET Framework 4.8 with a WebView2 window; the UI is plain HTML, CSS and JavaScript with no build step. One list of operations in `Api.cs` serves both the window and the MCP server.

- **MCP server inside the app:** 45 tools on `127.0.0.1:47700`. They act on the open window, so you watch every edit happen, and nothing reaches the driver until `apply` is called. It refuses any request whose `Host` or `Origin` isn't local.
- **Releases:** every push to main builds a 1.1 MB zip with the signed driver bundled. The app checks GitHub at start-up, verifies the SHA-256 and swaps the files when it closes.
- **Website:** a static page on Cloudflare Workers at accel.solarquack.in.
- **The film on this page:** an SVG scene drawn frame by frame in HTML from one `seek(t)` function and captured with Playwright. The curves are the driver's real output pulled through the app's own MCP server, and the music and sound effects are synthesised in Python on a 128 BPM grid.

## 04 // LEARNED
- Keeping one copy of the curve math, the driver's, removed a class of bugs where the plot and the mouse disagreed.
- cm/360 and speed units were off until I accounted for the driver's DPI normalisation per device.
- The hash check catches a damaged download; it doesn't prove who published it. The README says that rather than calling updates "secure".

What isn't done yet: dragging, hovering and keyboard shortcuts were checked through MCP and window captures, not yet by hand on every control.
